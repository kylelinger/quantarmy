## Session 10 续2 (~10:49 IST) - V2 架构设计

### V2_DESIGN.md 完成 (commit `13aecb9`, ~500行)

#### 核心架构决定: Agent vs Skill vs Tool 三层
- **Agent** = 有人格+记忆+辩论能力的角色 (可换整个Agent)
- **Skill** = 可插拔计算模块 (可从GitHub导入)
- **Tool** = 系统API (固定不可换: getKlines, getDepth等)
- **结论**: 每个角色是Agent，装备多个Skills

#### V2 五阶段Pipeline
1. Data Collection (5s) - Collector采集
2. Independent Analysis (3-5s) - 6角色并行
3. Debate (3-8s, 2轮) - 自动匹配辩论对
4. CEO Decision (2-3s) - 加权共识+追问
5. Memory Update - 存储分析历史

#### 辩论对匹配
- Strategist vs RiskOfficer (进攻vs防守)
- Analyst vs Researcher (形态vs统计)
- CTO审计所有人 (特权)

#### 记忆系统三层
- Short-term: 当次分析session内存
- Long-term: 每Agent每标的历史判断 (localStorage)
- Meta-memory: 从long-term计算自我认知 ("我BTC做多准确率68%")

#### 实现路线
- V2.0: 规则引擎辩论 (无需LLM, 免费快速) - 4-6 sessions
- V2.1: LLM增强 (自然语言辩论, 需API key) - 2-3 sessions

#### 新文件目录规划
- `lib/agents/` - 8个Agent定义
- `lib/debate/` - 辩论引擎
- `lib/memory/` - 记忆系统
- `lib/skills/` - Skill注册表+加载器
- `components/Debate/` - 辩论可视化

#### 4个待CEO决定的问题
1. V2.0规则引擎 vs 直接LLM → CTO建议规则引擎
2. 记忆localStorage vs 后端 → CTO建议先localStorage
3. 辩论自动 vs 手动触发 → CTO建议默认自动
4. 用户旁观 vs 参与辩论 → CTO建议V2.0先旁观
